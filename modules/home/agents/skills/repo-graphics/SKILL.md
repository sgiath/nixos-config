# Repo Graphics

Generated SVG graphics for READMEs: a minimalist dark card with computed
line-work, in one consistent visual style across all repos.

## Core Principles

1. **Computed, not drawn.** Every graphic is real output of the repo's domain:
   real equations, real data, real protocol geometry (planetary orbits from
   ephemerides, `y² = x³ + 7` with chord-and-tangent addition, a real signal
   waveform...). Never clipart, never decorative abstract shapes.
2. **Committed generator.** A dependency-free script in the repo's own
   language (e.g. `docs/graphics.exs`, stdlib only) computes the geometry and
   writes the SVG. The SVG carries
   `<desc>Generated by <script path> — <what it shows>. Do not edit by hand.</desc>`.
3. **User picks the concept.** Never decide the subject unilaterally — draft
   several candidates first (see Workflow).
4. **Verified in a browser.** Screenshot against both GitHub-light and
   GitHub-dark backgrounds before delivering.

## Workflow

1. **Understand the domain.** Read the README and main modules. What real
   math/data/structure does this repo own?
2. **Propose 3–5 candidates.** Each must be visually interesting AND
   domain-relevant. One sentence each: what real thing it draws.
3. **Draft all candidates.** Generate quick SVG drafts in the house style
   (skip polish: no animation, rough labels). Screenshot each with the
   browser tool and present them to the user for a pick — offer one option per candidate with its screenshot.
   Also ask whether the winner becomes a header banner or standalone content
   graphics.

   Wait for the user's chosen concept and surface before building the final
   artifact or editing the README. A choice already supplied by the user
   satisfies this gate; do not ask them to repeat it.

4. **Build the final artifact** — only after the gate — from the chosen
   concept, as either:
   - **Header banner** — 820×220 caption card at the top of the README, or
   - **Content graphics** — larger standalone diagrams embedded in the README
     body.
   Polish: exact geometry, label placement, subtle animation, collision checks.
5. **Wire into the README** (see Embedding) and delete rejected drafts.
6. **Verify**: light+dark browser screenshots, repo formatter on the script,
   the existing README formatting convention. Remind the user raw URLs resolve only after push.

## Visual Style

See [references/style.md](./references/style.md) for full palette, layout
templates, and copy-paste SVG skeletons. The invariants:

- **Card**: near-black `#050505`, hairline border `#1c1c1f`, `rx="12"`,
  content clipped by an inset `rx="11"` rect. Line-work may bleed through the
  clip edges — it makes the card feel alive.
- **Line-work**: thin monochrome `#e6e6e9` strokes (width 1–1.2) with an
  opacity hierarchy: hero 0.5–0.7, construction/secondary 0.2–0.35, backdrop
  0.05–0.1.
- **One accent.** Exactly one accent color per graphic, on the single most
  meaningful node (the sun, `R = P + Q`). Pick per project: bitcoin orange
  `#f7931a`, terminal green `#4ade80`, warm red `#e25d52`, or similar.
- **Typography**: `ui-monospace, 'JetBrains Mono', 'Fira Code', monospace`,
  UPPERCASE letterspaced captions. Header caption: title 24px / weight 300 /
  letter-spacing 8 / `#e6e6e9`; subtitle 9px / letter-spacing 3 / `#606069`.
  In-diagram labels 9–11px `#606069` (accent color on the accent node's label).
- **Animation**: subtle SMIL only, long periods (20s+): `animateTransform`
  rotations, `animateMotion` along a computed path, opacity blinks. GitHub
  renders SMIL inside `<img>`; never JS.

## Generator Conventions

- Location: `docs/` or `examples/`; stdlib only; one module, module attributes
  for palette and plot window, `fmt/1` rounding floats to 2 decimals.
- Compute everything: intersections, reflections, orbital positions. No
  hand-placed magic coordinates except text blocks and label nudges.
- Target 5–15 KB per SVG (sample curves at 300–400 steps).
- Run the repo formatter on the script; expect Styler/formatter comment moves
  and re-check them.

## Embedding

- README references the artifact via
  `https://raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>` with alt
  text describing the real content (not "logo").
- Header banner: `<p align="center"><img .../></p>` at the very top, above
  the H1.
- Content graphics: side-by-side `width="49%"` pair (or a single `66%`) in
  `<p align="center">`, followed by a short caption paragraph linking the
  generator script.

## Verification

Build a throwaway HTML page embedding the SVG(s) twice — on `#ffffff` and on
`#0d1117` — and capture both with the browser tool. In T3, `html_preview` can render the self-contained wrapper and
inline local SVG paths for screenshot inspection; use collaborative preview tools when interacting with a live page.
Outside T3, use the available browser's full-page capture. Check: label
collisions, caption/graphic overlap, clip behavior at card corners, contrast
on both backgrounds. Standalone SVG tabs may tile artifacts; only trust the
`<img>`-embedded preview.
